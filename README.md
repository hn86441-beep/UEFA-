# دوري الأبطال — منصة إدارة الدوري

موقع لإدارة دوري كرة قدم: إضافة/تعديل/حذف الفرق، تعديل النقاط، إنشاء المجموعات
وإجراء القرعة، تسجيل نتائج المباريات، وقرعة الأدوار الإقصائية (خروج المغلوب) —
كل ذلك من لوحة تحكم محمية بكلمة سر لا يصل إليها إلا أنت.

## بنية المشروع — 17 ملفًا فقط

هذا مشروع Next.js (App Router) بأقل عدد ممكن من الملفات دون التضحية بأي ميزة:
كل نقاط الـ API مجمّعة في ملف واحد ديناميكي، وكل الصفحات العامة (الترتيب/المجموعات/خروج
المغلوب) في صفحة رئيسية واحدة بتبويبات، ولوحة التحكم (تسجيل الدخول + الإدارة) في صفحة
واحدة أيضًا.

⚠️ **قبل الرفع: احذف كل الملفات الموجودة حاليًا في مستودعك على GitHub أولًا**، ثم ارفع
هذه الملفات بنفس المسارات تمامًا. المجلد الذي اسمه `[...path]` **يجب** أن يحتفظ بالأقواس
والنقاط الثلاث كما هي — هذا أسلوب Next.js لتوحيد كل نقاط الـ API في ملف واحد.

```
.env.example
.gitignore
README.md
next.config.js
package.json
postcss.config.js
tailwind.config.js
middleware.js

app/
  layout.js
  globals.css
  page.js                      ← الصفحة العامة الكاملة (تبويبات: الترتيب / المجموعات / خروج المغلوب)
  admin/
    page.js                    ← تسجيل الدخول + لوحة التحكم الكاملة في ملف واحد
  api/
    [...path]/
      route.js                 ← كل نقاط الـ API (فرق، مجموعات، مباريات، قرعة، تسجيل دخول...)

components/
  Nav.jsx

lib/
  logic.js                     ← دوال الترتيب والقرعة (مشتركة)
  server.js                    ← تخزين البيانات + جلسة المشرف (خادم فقط)
  useLeagueData.js              ← خطّاف جلب البيانات من المتصفح
```

**ملاحظة عن `[...path]`:** هذا مجلد واحد فقط باسم خاص، وليس عدة مجلدات. أي طلب مثل
`/api/teams` أو `/api/matches/abc123` أو `/api/auth/login` يمر جميعه عبر ملف
`app/api/[...path]/route.js` الوحيد، الذي يفرّق بين الطلبات داخليًا بالكود.

## خطوات النشر على Vercel عبر GitHub

### 1) ارفع المشروع على GitHub
احذف كل الملفات الحالية في المستودع وارفع محتوى هذا المشروع بنفس بنية المجلدات أعلاه.

### 2) استورد المشروع في Vercel واضبط Framework Preset
من [vercel.com](https://vercel.com) اضغط **Add New → Project** واختر مستودعك.

**تنبيه مهم:** تأكد أن **Framework Preset** مضبوط على **Next.js** وليس **Node.js** أو
**Other**. إن كان خطأً: **Settings → General → Framework Preset** غيّره إلى **Next.js**،
تأكد أن **Root Directory** يشير لجذر المستودع، ثم **Deployments → Redeploy**.

### 3) أنشئ قاعدة بيانات مجانية على Upstash مباشرة (وليس عبر Vercel)
تبويب Storage داخل Vercel أحيانًا يوجّهك نحو خطط مدفوعة حتى للاستخدام البسيط. لتفادي ذلك
تمامًا، أنشئ القاعدة من موقع Upstash نفسه مباشرة، وهو مجاني فعليًا بدون بطاقة ائتمان:

1. اذهب إلى **upstash.com** وأنشئ حسابًا مجانيًا (يمكن الدخول مباشرة بحساب GitHub)
2. من لوحة تحكم Upstash: **Create Database** → اختر اسمًا (مثلًا `league-db`) → اختر
   **Regional** (وليس Global، أرخص وكافٍ لموقع صغير) → اختر أقرب منطقة لك → **Create**
3. بعد الإنشاء، ستفتح صفحة القاعدة — انزل لقسم **REST API** وستجد فيه قيمتين:
   `UPSTASH_REDIS_REST_URL` و`UPSTASH_REDIS_REST_TOKEN`
4. انسخ القيمتين، وأضفهما في مشروعك على Vercel من **Settings → Environment Variables**
   بنفس الاسمين تمامًا: `UPSTASH_REDIS_REST_URL` و`UPSTASH_REDIS_REST_TOKEN`

بدون هذه الخطوة، أي تعديل تجريه (فريق جديد، نقاط، مقطع صوتي مخصّص...) لن يُحفظ بشكل دائم.
كل شيء — بما فيه المقاطع الصوتية القصيرة (أقل من 10 ثوانٍ) — يُحفظ في نفس هذه القاعدة،
بلا حاجة لأي خدمة تخزين ملفات منفصلة.

### 4) أضف باقي متغيرات البيئة
من نفس صفحة **Settings → Environment Variables** في Vercel أضف أيضًا:
- `ADMIN_PASSWORD` = كلمة السر لدخول لوحة التحكم
- `SESSION_SECRET` = نص عشوائي طويل وسري

### 5) أعد النشر (Redeploy)
بعد إضافة كل ما سبق، أعد نشر المشروع من تبويب **Deployments**.

### 6) افتح لوحة التحكم
`https://YOUR-SITE.vercel.app/admin` وسجّل الدخول بكلمة السر التي حددتها.

## التطوير محليًا (اختياري)

```bash
npm install
npm run dev
```

بدون ربط Vercel KV، يحفظ الموقع البيانات محليًا في `data/league.local.json` (لجهازك فقط
أثناء التطوير، وليس مناسبًا للاستضافة الفعلية).
